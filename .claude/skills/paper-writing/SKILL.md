# Paper Writing

## Structure (`paper/sections/`)
| File | Content | Length (IEEE 2-col, 6–8 pages total) |
|---|---|---|
| 00-abstract | problem · method · key numbers · takeaway | 150–200 words |
| 01-introduction | context → problem → gap → RQs → contributions (bulleted) → paper outline | ~1 page |
| 02-related-work | themes from `literature-review` skill, each ending with the gap | ~0.75 page |
| 03-methodology | design, apps & parity, models, devices, protocol, metrics, statistics | ~1.5 pages |
| 04-results | one subsection per RQ: figure/table → what it shows → numbers | ~2 pages |
| 05-discussion | why (decomposition), guidelines table for developers, surprises | ~0.75 page |
| 06-threats | internal / construct / external / conclusion validity | ~0.3 page |
| 07-conclusion | answers to RQs, future work | ~0.3 page |

## Rules
1. **Traceability:** every number comes from `paper/tables/*.tex` / figures generated by
   `benchkit`, or is directly cited. Unknown yet? Write `\todo{...}`. Never write a placeholder number.
2. **Citations:** only keys present and verified in `literature/references.bib`.
3. **Methodology section is derived from** `docs/02-methodology.md`, `docs/03-metrics.md` and ADRs,
   so keep them consistent. If the doc changes, the section changes.
4. **Style:** specific, plain, active voice. Past tense for what we did, present for what results show.
   Avoid hype ("revolutionary", "crucial", "delve", "leverage", "in today's fast-paced world").
   One idea per paragraph; topic sentence first.
5. **Figures:** every figure is referenced in text before it appears, caption is self-explanatory
   (what, where, how many runs, what error bars mean).
6. **Authenticity:** the author must be able to explain every sentence in a viva. AI drafts are
   starting points. Mark AI-drafted paragraphs `% AI-draft` until the author rewrites/approves them.

## Workflow per section
1. Bullet outline as LaTeX comments in the section file.
2. Draft prose under each bullet.
3. Check every claim: cite or `\ref` a figure/table.
4. Run `make paper` (or compile on Overleaf). Fix warnings (undefined refs/cites).
5. Update section status in `docs/PROGRESS.md`.
