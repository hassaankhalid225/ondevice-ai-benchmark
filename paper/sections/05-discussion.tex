\section{Discussion and Practitioner Guidelines}\label{sec:discussion}

Campaign EXP-001 demonstrates that cross-platform on-device AI performance cannot be reduced to FFI invocation speed alone: ecosystem packaging defaults, pure-Dart data pipelines, and asset memory semantics shape user-perceived latency and RAM far more than crossing the language boundary. Below we explain the architectural mechanisms behind our measurements and formalize practitioner guidelines.

\subsection{Architectural Mechanisms Behind Observed Gaps}
\textbf{Pure GPU Kernel Parity vs.\ Preprocessing Bottleneck:} Once tensors reside in native buffers and compute executes on hardware shaders, Flutter and Native Android achieve statistical and practical equivalence ($\mathcal{R} = 0.99\text{--}1.04$, $p_{\mathrm{Holm}} = 1.000$). The sharp end-to-end penalty on vision tasks ($1.91\times\text{--}2.00\times$ under GPU EfficientDet-Lite0) originates upstream in JPEG decoding and bilinear resizing via pure Dart's \texttt{image} library ($68.53\text{--}103.17$\,ms vs.\ $8.64\text{--}24.56$\,ms in Android's native codecs). Notably, this bottleneck halves GPU acceleration returns: Native EfficientDet-Lite0 FP32 amortizes its $2.35$\,s OpenCL shader warm-up within $32$ inferences, whereas Dart preprocessing stretches Flutter's break-even horizon to $114$ inferences---and eliminates GPU end-to-end wins altogether on PowerVR INT8 inference ($176.17$\,ms GPU vs.\ $154.51$\,ms CPU).

\textbf{Package Defaults Matter More Than FFI Latency:} Auditing release binaries uncovered three subtle \texttt{tflite\_flutter}~0.12.1 behaviors invisible at the Dart API surface (ADR-0009). First, \texttt{pub.dev} pulled \texttt{litert:1.4.0} (version~\texttt{2.20.0}) with default single-thread \texttt{XNNPackDelegate(nullptr)}, outperforming Maven's pinned \texttt{tensorflow-lite:2.16.1} 4-thread configuration on FP32 CPU models ($\mathcal{R} = 0.50\text{--}0.75$) due to lower Cortex-A53 thread contention and newer kernels. Second, \texttt{Interpreter.fromAsset()} copies flatbuffers via \texttt{rootBundle} into C heap using \texttt{calloc<Uint8>} without invoking \texttt{calloc.free()} on delete, inflating Flutter's incremental model+runtime PSS ($+7.24$ to $+83.18$\,MiB over Native's zero-copy \texttt{mmap}) and slowing large CPU model initialization ($3.74\times\text{--}11.71\times$). Third, passing nested \texttt{List<List<double>>} start/end logits in \texttt{QATask} lifts relative FFI boundary cost to $11.90\times\text{--}18.22\times$ ($2.76\text{--}4.63$\,ms vs.\ $0.21\text{--}0.32$\,ms), which stays negligible on slow CPU runs yet creates a practically significant $+4.90$\,ms ($1.09\times$) end-to-end tax on fast GPU MobileBERT-QA.

\subsection{Actionable Optimizations for Flutter Engineers}
Teams shipping LiteRT inside Flutter can eliminate most observed penalties without abandoning cross-platform UI development:
\begin{enumerate}
    \item \textbf{Bypass Pure-Dart Image Decoding:} Expose raw camera YUV/RGBA planes or native \texttt{Bitmap} resizing via a slim MethodChannel/JNI plugin before writing into pre-allocated tensor buffers; on GPU EfficientDet-Lite0 this targets the $76\text{--}79$\,ms preprocessing delta ($>90\%$ of Flutter's end-to-end slowdown).
    \item \textbf{Prefer File-Backed \texttt{mmap} and Flat \texttt{TypedData}:} Extract large $\ge 5$\,MB flatbuffers once to app storage and initialize via \texttt{Interpreter.fromFile()} instead of \texttt{fromAsset()} to avoid unfreed \texttt{calloc} resident copies and cut CPU model-load latency ($3.7\times\text{--}11.7\times$). Replace nested output \texttt{List} allocations with flat \texttt{Float32List}/\texttt{Int32List} views to reduce FFI \texttt{boundary\_overhead\_ms}.
    \item \textbf{Pin XNNPACK Options and Match Precision to Silicon:} Explicitly construct \texttt{XNNPackDelegate} thread counts suited to target BIG.little topologies rather than inheriting library defaults, use INT8 models primarily on CPU/NNAPI delegates ($26\%\text{--}57\%$ faster compute, $18\%\text{--}27\%$ lower PSS), and prefer FP32 when targeting entry-tier mobile GPUs lacking native INT8 shaders.
\end{enumerate}
