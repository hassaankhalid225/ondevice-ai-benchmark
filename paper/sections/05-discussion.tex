\section{Discussion and Practitioner Guidelines}\label{sec:discussion}

The empirical findings from our benchmark provide clear answers to long-standing questions regarding cross-platform on-device machine learning efficiency. In this section, we analyze the underlying architectural mechanisms and formulate evidence-based guidelines for mobile software architects.

\subsection{Why Pure Inference Achieves Parity While End-to-End Lags}
A central finding of this study is the sharp dichotomy between pure kernel execution ($\text{inference\_native\_ms}$) and end-to-end duration ($\text{end\_to\_end\_ms}$). Because `tflite\_flutter` utilizes Dart FFI to invoke the identical C dynamic library (`libtensorflowlite.so`) employed by Native Android, the underlying computational graph, matrix multiplications, and hardware delegate acceleration proceed with zero software penalty once the invoke call is dispatched.

The performance divergence observed in real-world Flutter applications is overwhelmingly an artifact of \textbf{data ingestion and preprocessing}. When mobile software engineers implement on-device deep learning in Flutter using standard package dependencies (e.g., the pure Dart `image` package), image decoding, pixel unpacking, and bilinear interpolation occur within the managed Dart runtime. In contrast, Native Android leverages hardware-accelerated C++ bitmap decoders (`libjpeg-turbo` / Android framework decoders) optimized specifically for mobile ARM SIMD instruction sets.

\subsection{Actionable Recommendations for Flutter Developers}
For teams building production AI-powered applications in Flutter, our findings suggest three concrete optimizations:
\begin{enumerate}
    \item \textbf{Decouple Image Preprocessing from Dart:} For camera-driven vision models, developers should avoid decoding full-resolution camera frames in Dart. Utilizing camera plugins that expose direct YUV/NV21 native buffers and performing resizing via native Android/iOS native bindings eliminates over 80\% of the Flutter latency gap.
    \item \textbf{Prioritize INT8 Quantization:} In addition to reducing model size and enabling NPU acceleration, INT8 quantization reduces input and output tensor byte volumes by $75\%$, directly minimizing the memory copying cost across the Dart FFI boundary.
    \item \textbf{Avoid Main-Isolate Blocking:} While our primary study benchmarks the standard main-isolate developer path, compute-intensive preprocessing should be isolated within a background Dart worker isolate (`compute()`) in production to prevent UI frame drops.
\end{enumerate}
