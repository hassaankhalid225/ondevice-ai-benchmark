\section{Threats to Validity}\label{sec:threats}

\textbf{Internal Validity:} Two measurement artifacts affect our campaign on the Infinix Hot~8. First, default dependency resolution caused Flutter's \texttt{tflite\_flutter}~0.12.1 to link LiteRT~2.20.0 with default \texttt{XNNPackDelegate(nullptr)} while Native linked TensorFlow Lite~2.16.1 with 4-thread XNNPACK. Thus, default CPU findings capture ecosystem packaging effects rather than pure language-boundary cost; GPU results remain independent of XNNPACK. Controlled matched-version runs with explicit $1$- and $4$-thread XNNPACK pins are needed in future work to isolate pure FFI overhead on CPU. Second, seven Native runs ($840$ records) suffered a MediaTek/Android~9 clock-overflow sentinel ($9.22 \times 10^{15}$\,ms) and were auditably excluded via version-controlled rules alongside four Session-1 INT8 dtype setup errors and seven missing runs across Sessions~1 and~3, leaving $n_F=8$ and $n_N \in \{5,7,8\}$ complete session replicates. Third, Native MobileNetV3-Large CPU exhibited bimodal session medians attributable to Cortex-A53 scheduler/DVFS transitions: $92.4\text{--}129.7$\,ms vs.\ $232.4\text{--}358.0$\,ms on FP32 (aggregate median $129.67$\,ms), and $71.0\text{--}77.8$\,ms vs.\ $341.7\text{--}346.5$\,ms on INT8 (median $77.75$\,ms), widening ratio confidence intervals. Finally, both harnesses were implemented by a single author, introducing potential implementation bias; we mitigate this by enforcing an identical execution contract, deterministic inputs, $500/500$ output-digest checks, and releasing all harness code publicly for audit.

\textbf{Construct Validity:} Timing relies on Dart \texttt{Stopwatch} ($\mu$s) and Android \texttt{elapsedRealtimeNanos()} (ns), whose nested boundaries agree within $0.001$\,ms. Linux \texttt{/proc/self/stat} tick quantization near $10$\,ms yields occasional $0.0\%$ readings on fast ($<60$\,ms) Native MobileBERT INT8 GPU runs. Memory uses MiB ($\text{KiB}/1024$) while APK disassembly uses decimal MB ($10^6$\,B) restricted to the shared \texttt{arm64-v8a} ABI to exclude Flutter's extra \texttt{x86\_64} slice. Because $T_{\mathrm{load}}$ records at warm-up iteration~0, OS page cache warmth can vary across in-session runs, whereas cold launch and idle PSS use $n=10$ dedicated force-stopped launches. All sessions stayed tethered at nominal thermal status (\texttt{none}); unplugged battery charge-counter energy drain and 5-minute sustained throttling remain unmeasured in this study.

\textbf{External Validity:} Measurements cover one entry-tier handset (Infinix Hot~8, Helio~P22, PowerVR~GE8320, Android~9/API~28), three models under 22\,MB, and LiteRT runtimes. Android~9 lacks mature vendor NNAPI HAL acceleration and Impeller Vulkan support~\cite{flutterimpeller2025}, while entry-tier PowerVR lacks native INT8 GPU shaders. Quantitative latencies and delegate rankings should not be extrapolated without re-measurement to Android~12+ mid/flagship NPU/GPU devices, iOS Core~ML targets, ONNX Runtime/ExecuTorch, or multi-billion-parameter language models.

\textbf{Conclusion Validity:} Operating strictly on independent session medians ($n_F=8$, $n_N \in \{5,7,8\}$) prevents iteration-level pseudo-replication, while Holm--Bonferroni controls family-wise Type-I error ($\alpha=0.05$) within each RQ family. Under smaller sample sizes ($n_N=5$ on EfficientDet INT8 GPU and MobileNetV3 FP32 CPU), Mann--Whitney~$U$ reaches a discrete two-sided floor $p_{\min}=0.001554$; within larger families such as RQ2 ($M=50$) or non-minimum ranks ($U \ge 1, p=0.00535$), $(8,5)$ comparisons cannot achieve adjusted significance unless dominating at least 18 stronger rejections. We therefore pair Holm $p$-values with Cliff's~$\delta$, bootstrap CIs, and explicit non-parametric TOST bounds so inconclusive underpowered tests (such as EfficientDet INT8 GPU, $p_{\mathrm{TOST}}=0.177$) are never misclassified as equivalent.
