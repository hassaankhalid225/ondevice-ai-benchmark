\section{Threats to Validity}\label{sec:threats}

We identify four categories of potential validity threats and detail our mitigation protocols:

\textbf{Internal Validity:} System thermal throttling and dynamic voltage/frequency scaling (DVFS) represent significant confounding variables in mobile benchmarking~\cite{almeida2021smart}. Uncontrolled heating rapidly depresses clock speeds, which could cause later configurations to appear artificially slower. We mitigated this by enforcing mandatory 60-second cooldown intervals between configurations, verifying that thermal status is $\le \text{light}$ before run initialization, and discarding runs that reach severe thermal throttling. Furthermore, background network synchronization and notification noise were eliminated by maintaining all devices in Airplane Mode with disabled radios and fixed display brightness. To control for compilation artifacts, both applications were compiled strictly in release mode with optimizations enabled.

\textbf{Construct Validity:} Construct validity concerns whether our metrics accurately capture the intended concepts. In accordance with ADR-0006, measuring pure inference time via the runtime's internal invoke timer ($\text{inference\_native\_ms}$) isolates neural network kernel execution from FFI wrapper code. However, because Dart utilizes monotonic `Stopwatch` (microsecond resolution) while Android utilizes `SystemClock.elapsedRealtimeNanos()`, minor clock precision variations exist. Battery drain measurement via Android's `BatteryManager.BATTERY_PROPERTY_CHARGE_COUNTER` is a software proxy with coarse granularity ($\sim 1\dots 5\,\mu\text{Ah}$ resolution); we report this explicitly as an operational proxy rather than true physical energy draw from a hardware monsoon power monitor.

\textbf{External Validity:} Our empirical findings are obtained on Android devices executing Google LiteRT 2.16.1 across vision and language architectures under 25\,MB. While LiteRT represents the predominant mobile deep learning runtime in production apps~\cite{xu2019first}, our results do not automatically generalize to other runtimes (such as ONNX Runtime, MediaPipe, or ExecuTorch), nor to large on-device language models ($> 1\text{B}$ parameters) that exceed mobile memory constraints. Similarly, while Flutter's cross-platform architecture mirrors other AOT-compiled frameworks, specific timing dynamics on Apple iOS (utilizing Core ML delegates) remain an area for future empirical confirmation.

\textbf{Conclusion Validity:} To prevent false positive statistical significance resulting from pseudo-replication, we designated the session median ($n=8$ independent runs per platform per configuration) as the primary unit of analysis (ADR-0007), rather than pooling thousands of non-independent iterations. To guard against family-wise error rate inflation across multiple hypothesis tests, all $p$-values were adjusted using the Holm--Bonferroni step-down procedure within each research question family. Finally, we emphasized non-parametric Cliff's delta effect sizes and bootstrap confidence intervals over $p$-values alone.
