\section{Conclusion and Future Work}\label{sec:conclusion}

This paper presented EXP-001, a controlled full-factorial empirical benchmark quantifying the latency, pipeline stage, memory, CPU, startup, and binary size impacts of embedding LiteRT models inside Google Flutter versus Native Android (Kotlin). Over 24,020 raw measurements (23,180 retained records across 8 alternating sessions), 10 cold-start/idle trials, and APK binary disassembly on an entry-tier smartphone, we answer RQ1--RQ5 as follows:
\begin{enumerate}
    \item[\textbf{RQ1:}] On hardware-accelerated GPU delegates, pure runtime inference (\texttt{inference\_native\_ms}) achieves full statistical and practical equivalence between Flutter and Native Android ($\mathcal{R} = 0.99\text{--}1.04$, $p_{\mathrm{Holm}} = 1.000$). On CPU, default \texttt{pub.dev} vs.\ Maven dependencies introduce runtime version and XNNPACK threading drift (LiteRT~2.20.0 single-threaded vs.\ TFLite~2.16.1 4-threaded), making stock Flutter faster on FP32 MobileBERT-QA ($\mathcal{R}=0.50$, $p_{\mathrm{Holm}}=0.003$) and EfficientDet-Lite0 ($\mathcal{R}=0.75$, $p_{\mathrm{Holm}}=0.042$).
    \item[\textbf{RQ2:}] Vision end-to-end penalties ($1.91\times$--$2.00\times$ on GPU EfficientDet-Lite0) stem predominantly from pure Dart image decoding and resizing ($4.20\times$--$10.48\times$ slower than Android framework decoding). Dart FFI marshalling adds $0.88\text{--}4.63$\,ms ($11.90\times$--$18.22\times$ relative on nested MobileBERT logits), contributing a $+4.90$\,ms end-to-end tax on GPU NLP ($1.09\times$).
    \item[\textbf{RQ3:}] Flutter incurs both a $+37.99$\,MiB fixed idle baseline penalty ($71.29$ vs.\ $33.30$\,MiB, $2.14\times$) and a $1.25\times$--$3.06\times$ larger incremental model/runtime PSS footprint ($107.86\text{--}200.36$\,MiB steady state vs.\ $55.77\text{--}86.64$\,MiB Native), driven by Dart isolate allocations and unfreed \texttt{calloc} asset loading instead of Native zero-copy \texttt{mmap}. Unplugged energy and thermal throttling remain deferred to non-tethered runs.
    \item[\textbf{RQ4:}] Non-kernel overhead varies from $60.9\%\text{--}65.3\%$ of end-to-end time on GPU vision down to $3.0\%\text{--}3.4\%$ on CPU NLP, governed more by input modality than FLOP count ($\rho = -0.39, p = 0.260$). Within vision models, GPU acceleration exposes and amplifies the relative Dart preprocessing penalty ($\mathcal{R}=1.17 \to 2.00$), stretching GPU shader-compilation break-even from $32$ Native inferences to $114$ Flutter inferences, while INT8 yields $26\%\text{--}57\%$ CPU speedups and $18\%\text{--}27\%$ PSS savings yet degrades entry-level PowerVR GPU inference.
    \item[\textbf{RQ5:}] Flutter extends cold-launch \texttt{TotalTime} by $+45.5$\,ms ($468.50$ vs.\ $423.00$\,ms, $\mathcal{R}=1.11$, $p_{\mathrm{Holm}}=0.005$), adds $+16.79$\,MB single-ABI \texttt{arm64-v8a} footprint ($123.83$\,MB vs.\ $65.63$\,MB universal APKs), and slows larger CPU model loading by $3.74\times$--$11.71\times$, while GPU shader warm-up ($1.63\text{--}4.20$\,s) equalizes both stacks.
\end{enumerate}

\subsection{Future Work}
Planned follow-on campaigns build directly on this open-source testbed:
\begin{itemize}
    \item Expanding physical execution across mid-range and flagship Android hardware tiers (\texttt{EXP-002+}) alongside pinned matched-version LiteRT binaries and explicit multi-thread XNNPACK / file-\texttt{mmap} Flutter controls to separate library drift from intrinsic framework overhead.
    \item Conducting unplugged battery charge-counter energy campaigns and 5-minute sustained thermal FPS runs.
    \item Porting the harness contract to Apple~iOS (Swift vs.\ Flutter over Core~ML delegates) and extending workloads to quantized on-device Small Language Models (SLMs).
    \item Evaluating a drop-in native camera YUV/bitmap preprocessing and \texttt{mmap} loader plugin to verify recovery of native end-to-end and memory parity inside Flutter.
\end{itemize}
